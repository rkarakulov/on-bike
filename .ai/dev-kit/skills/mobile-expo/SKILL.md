# mobile-expo — процесс для универсального приложения

Правила — `.claude/rules/*.md` проекта для путей приложения, канон — `AGENTS.md` §4. Сначала план экрана,
потом код. Приложение одно: iOS, Android и браузер (мобильный веб / PWA) с тем же функционалом.

## 0. Рамки продукта (проверь первым)

Рамки — `AGENTS.md` §1 и инвариант «нет на вырост» (§4). Задача требует возможности вне рамок
(например push, фоновая геолокация, BLE, внешние IdP) — стоп, это продуктовое решение и ADR, а не реализация.

## 1. План экрана

- **Маршрут** в каталоге маршрутов Expo Router (`src/app/` или по `AGENTS.md` §2): путь, параметры,
  guard авторизации, гостевой режим. Не-роутовый код — вне каталога маршрутов.
- **Deep link / universal link:** какой объект открывает экран; https-URL открывается без установки
  приложения (в вебе); возврат к объекту после входа/регистрации.
- **Данные:** запросы через API-клиент проекта (поверх `@rkarakulov/api-client-core`); статусы фоновой
  обработки — по правилам проекта (polling, если реального времени нет в рамках).
- **Состояния:** по инварианту «состояния данных» `AGENTS.md` §4 через `AsyncContent` и скелетоны
  `Skeleton*` из `@rkarakulov/ui`: какой скелетон повторяет раскладку экрана, что видно сразу.
- **Дизайн-система:** экран собран из компонентов `@rkarakulov/ui` (Button, TextField, DateField, Banner,
  Skeleton, AsyncContent…) и семантики `useTheme()` (тема и шрифты — `configureDesignSystem` в корне приложения); бренд и темы проекта — через
  `defineThemes(...)` + `configureDesignSystem(...)`. Чего не хватает — расширяй систему, а не стиль по месту: общий компонент или
  токен — в базе app-foundation (`@rkarakulov/ui` / `@rkarakulov/design-tokens`, отдельная задача и релиз);
  продуктовый компонент — в проекте по `AGENTS.md`, из токенов и с тестом. Примитивы и hex — нельзя.
- **Строки** — ключи `@rkarakulov/i18n-core` + словари проекта (`t('key', { param })`); множественное число
  и форматирование дат/чисел — через механизм пакета (`Intl`), таймзона явно. Тон и язык по умолчанию —
  `AGENTS.md` проекта.

## 2. Все платформы

- Каждый экран и каждая ссылка работают в iOS, Android и вебе/PWA с тем же функционалом; экран без
  web-варианта — дефект.
- Нативное — только за модулями с `.native` / `.web`-реализациями рядом; web-вариант пишется сразу.
- Публичные экраны объектов рендерятся на сервере (SSR) с OG-мета, если это требуют правила проекта.

## 3. Типовые возможности

- **Файлы:** системный picker; pre-check расширения, размера и пустого файла до загрузки;
  загрузка с процентом и отменой; поведение без сети — по правилам проекта.
- **Шеринг:** системный share sheet (в вебе — Web Share API или копирование ссылки); ссылка — https-URL.
- **Разрешения:** pre-permission экран, «Не сейчас», баннер со ссылкой в настройки ОС при отказе.
- **Удаление аккаунта:** подтверждение с последствиями (нативный alert / диалог в вебе).

## 4. Доступность и движение

`accessibilityLabel` / `accessibilityRole` / `accessibilityState`; `accessibilityActions` вместо
единственного drag-жеста; масштабирование шрифта; reduce motion — упрощённая анимация;
в вебе — фокус и клавиатура.

## 5. Нативное

Только через config plugins Expo (CNG): `ios/` и `android/` не коммитим. Новая нативная зависимость —
проверить совместимость с текущим SDK Expo, pnpm-монорепо и вебом, отметить в pr.md.

## 6. Проверка

Jest (jest-expo, хелперы `@rkarakulov/test-kit`) + Testing Library: состояния, навигация по deep link, формы.
Typecheck и тесты пакета приложения (`AGENTS.md` §3), `pnpm check`. Ручная проверка на симуляторе и в
браузере — в pr.md как `NOT VERIFIED`, если не делалась.
