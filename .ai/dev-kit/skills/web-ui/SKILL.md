# web-ui — процесс для админки

Правила — `.claude/rules/*.md` проекта для путей админки, канон — `AGENTS.md` §4. Сначала план, потом JSX.
Гостевой и пользовательский веб (страницы по ссылкам, PWA) — не здесь: это универсальное Expo-приложение,
процесс `mobile-expo`.

## 1. UI-план (до кода)

- **Экран и роль:** кто видит (роли из правил проекта), что делает; без роли — экран «Нет доступа».
- **Данные:** какие запросы через API-клиент проекта, какие схемы contracts; нет эндпоинта — сначала backend.
- **Компоненты:** что переиспользуем, что новое и где живёт (структура фич — по `AGENTS.md` §2 и правилам).
- **Состояния** каждого запроса — по инварианту «состояния данных» `AGENTS.md` §4 (скелетон по раскладке,
  ошибки с повтором, пусто; мутации — состояние кнопки); optimistic — если уместно.
- **Дизайн-система:** из чего собран экран — `@rkarakulov/ui` и токены `@rkarakulov/design-tokens`
  (семантические роли; в вебе — сгенерированные пакетом CSS-переменные и классы). Чего не хватает —
  токен/роль/компонент в базе app-foundation (отдельная задача и релиз) или продуктовый компонент в
  проекте из токенов — а не стиль по месту. Hex, примитивы и px-литералы оформления — нельзя.
- **Необратимые действия:** модалка с подтверждением; если проект ведёт append-only аудит — обязательная
  причина, которая уходит в аудит на сервере.
- **Строки** — ключи `@rkarakulov/i18n-core` + словари проекта; даты и числа — форматтеры пакета (`Intl`).

## 2. Типовые экраны админки

- Целевой viewport и темы — по правилам проекта.
- Плотные таблицы: сортировка, фильтры, пагинация, фиксированная шапка; фильтры видны во время загрузки.
- Формы: валидация по zod-схеме из contracts, ошибки сервера — на полях и баннером.
- Действие недоступно — кнопка заблокирована и объясняет почему.

## 3. Доступность

Семантические элементы, видимый фокус, клавиатурная навигация по таблицам и модалкам,
`aria-*` для нестандартных контролов, контраст по токенам.

## 4. Проверка

Тесты компонентов (Vitest + Testing Library) на состояния и действия; e2e (Playwright) для ключевых
сценариев, если проект их ведёт; `pnpm --filter <admin-пакет> build` и `pnpm check`.
