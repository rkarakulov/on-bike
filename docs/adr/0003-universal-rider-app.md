# 0003. Универсальное приложение райдера: iOS + Android + web/PWA + SSR гостевых страниц

- Статус: Accepted
- Дата: 2026-10-22
- Заменяет часть ADR-0001: гостевой веб на Astro (`apps/landing`) убирается.

## Контекст

Райдерам нужны четыре входа: приложение iOS, приложение Android, мобильный веб для тех, кто не ставит
приложение (в том числе PWA), и гостевые страницы по расшаренным ссылкам с OG-превью для мессенджеров
(заезд, маршрут, календарь, результат, карточка). Плюс веб-страницы для ссылок из писем (подтверждение
e-mail, сброс пароля), когда приложения нет.

В ADR-0001 гостевой веб — отдельное Astro-приложение. Это дублирует экраны (гостевой объект, подтверждение,
сброс) и стили второй раз — уже против AGENTS.md §4.11.

Expo SDK 58 (Expo Router 58) собирает тот же проект под веб на `react-native-web`, поддерживает
`web.output: 'server'` — рендеринг HTML на сервере на каждый запрос, `loader` маршрута для серверных данных,
`expo-router/head` для мета-тегов и адаптеры `expo-server`. Флаги `unstable_useServerRendering` /
`unstable_useServerDataLoaders` в SDK 58 объявлены устаревшими — поведение включено по умолчанию.

## Решение

0. **Веб — то же приложение, а не лендинг.** В браузере работает полноценное приложение райдера с тем же
   функционалом, что в iOS и Android: регистрация и вход, гонки, загрузка треков, маршруты, кофе-райды,
   календарь, профиль, уведомления. Любой экран и любая ссылка (из письма, шеринга, мессенджера) открываются
   в обычном браузере без установки — как сайт или PWA. Экранов «только для нативного приложения» нет;
   установленное приложение — удобство, не условие. Исключение из паритета — только через новый ADR.
1. **Одно Expo-приложение райдера** (`apps/mobile`) — источник для iOS, Android и web. Одни маршруты
   Expo Router, одни экраны, одна дизайн-система (`components/ui` на примитивах RN рендерятся в DOM через
   `react-native-web`).
2. **Web** — `web.output: 'server'`: публичные маршруты приложения (объект по расшаренной ссылке: заезд,
   маршрут, календарь, результат, карточка) рендерятся на сервере с `loader` + `<Head>` (OG-мета, картинка
   1200×630 — серверный рендер, ADR-0001) — это те же экраны, что видит гость в приложении, а не отдельный
   лендинг; дальше — обычная навигация после гидрации.
   Устанавливается как **PWA** (manifest, иконки, service worker со статикой; офлайн-данных нет).
3. **Платформенные развилки** — только файлами рядом: `.native.ts(x)` / `.web.ts(x)` внутри модулей
   (`features/auth/secure-storage`, `components/ui/date-field`, карта, шеринг). Экраны не знают о платформе.
4. **Сессия в вебе**: refresh-токен — только в httpOnly `Secure` `SameSite=Strict` cookie, выставляемой API
   для web-клиента; access-токен — в памяти. В нативных клиентах — SecureStore (как сейчас).
5. **Ссылки из писем** — https-URL одного приложения: в вебе открываются в PWA/SSR, в установленном
   приложении — через universal / app links (когда будет домен); в dev — `APP_LINK_BASE` из конфига.
6. **`apps/landing` (Astro) удаляется.** `apps/admin` («Протокол») остаётся отдельным Vite-приложением —
   другой продукт (десктоп, плотные таблицы); общие с райдером — токены, контракты, api-client, i18n.
7. Прод: гостевой веб/PWA обслуживает Node-процесс `expo-server` за Caddy вместо процесса landing
   (одна VPS, Docker Compose — без изменения сметы).

## Альтернативы

- **Astro для гостевых страниц + Expo только native** (ADR-0001): минимальный JS на гостевой странице, но
  дублирование экранов и стилей, а PWA — третий клиент. Отклонено человеком 2026-10-22.
- **Отдельное веб-приложение райдера на React DOM** с общими hooks: дублирование всего UI, две реализации
  дизайн-системы. Нет.
- **Universal UI на react-native-web и для admin** (как в webtrader): у панели другой UX и плотность,
  выигрыш мал, сложность высокая. Нет.

## Последствия

- **+** Один код экранов на 4 платформы; новые экраны сразу доступны в вебе; слайс 5 онбординга
  («веб-страницы ссылок») сводится к маршрутам, которые уже есть в приложении.
- **+** Дизайн-система одна (AGENTS.md §4.11) — без CSS-копии для гостевых страниц.
- **−** Гостевая страница тяжелее Astro (оценка 300–500 КБ JS); первый рендер — серверный HTML, SEO не страдает.
  Измерять на задаче-основе; при проблемах — code splitting маршрутов.
- **−** Нативные библиотеки нужно проверять на web-поддержку; без web — обязательная `.web`-реализация.
- **−** PWA на iOS ограничена (push у нас и так нет; установка — «На экран Домой»).
- **CI**: `expo export --platform web` и тесты компонентов в web-окружении; smoke Playwright для веба.
- **API**: эндпоинты сессии получают web-вариант (cookie) — до слайса 2 онбординга.
- Пересмотреть, если вес гостевой страницы или время первого рендера неприемлемы на реальных устройствах.
