### [HIGH] Запоздалый refresh может удалить cookie только что созданной сессии
- **status:** fixed (pass 1) — API сбрасывает cookie на 401 только если она пришла в запросе; web: refresh, poll регистрации и выход — под одним Web Lock `onbike.session-refresh`; тесты unit/int API и web (task.md §12 «Фиксы ревью pass 1»).
- **file:** apps/api/src/modules/identity/session.controller.ts
- **location:** 44–50
- **problem:** Любой 401 восстановления отправляет сброс cookie, включая запрос, отправленный без cookie до завершения регистрации. Если его ответ приходит после успешного `registration/poll`, браузер удаляет уже новую cookie.
- **why_it_matters:** Сценарий подтверждения предусматривает две вкладки. Вкладка письма запускает восстановление сессии, пока первая опрашивает регистрацию. При указанном порядке ответов первая вкладка показывает успешный вход, но перезагрузка теряет сессию. Токен регистрации уже использован, повторный обмен невозможен. Нарушается AC2–AC3.
- **evidence:** `RootLayout` вызывает `hydrate()` на каждом запуске; `session-persistence.web.ts:27` блокирует только `refreshSession()`. Опрос в `features/auth/queries.ts:53` выполняется вне этого замка, а `AuthController.poll:81` выставляет cookie. Здесь строка 50 безусловно сбрасывает её при 401. Проверка гонки в `session.int.test.ts` сравнивает статусы, но не итоговое состояние cookie браузера.
- **recommended_fix:** Сериализовать все операции, изменяющие cookie сессии, одним межвкладочным замком: восстановление, обмен регистрации и выход. Для запроса без cookie не отправлять её сброс. Добавить браузерный тест с задержанным ответом refresh: завершить poll, затем доставить старый 401 и проверить сохранение входа после перезагрузки.

### [MEDIUM] Инструкция первой web-сборки создаёт окружение слишком поздно
- **status:** fixed (pass 1) — `apps/app/.env` создаётся до `pnpm build:web` (runbook «Production-сборка», таблица README).

- **location:** 69–70
- **problem:** Предлагается выполнить `pnpm build:web`, а файл `apps/app/.env` создать только после сборки.
- **why_it_matters:** На чистой установке без экспортированной `EXPO_PUBLIC_API_URL` production-сборка останавливается. Пошаговая инструкция запуска не работает.
- **evidence:** `apps/app/src/lib/api.ts`, функция `apiBaseUrl()`, бросает `EXPO_PUBLIC_API_URL не задан для сборки`. В task.md §12 этот сбой также зафиксирован.
- **recommended_fix:** Перенести копирование и настройку `apps/app/.env` перед `pnpm build:web`; согласовать порядок с README.
