# Безопасность

Затронута зона ниже → в task.md обязателен Security checklist; reviewer без него ставит REQUEST CHANGES.

Зоны: аутентификация и сессии, роли, загрузка файлов, публичные ссылки и карточки, удаление аккаунта,
персональные и биометрические данные, внешние вызовы, инфраструктура и секреты.

## Security checklist (в task.md)

1. **AuthN/AuthZ:** кто может вызвать, где проверяется роль/владение объектом (на сервере, не в UI).
2. **Входные данные:** валидация по контракту, лимиты размера/количества, типы файлов по содержимому, не по расширению.
3. **Данные наружу:** нет лишних полей (биометрия, e-mail, телефон) в ответах и публичных ссылках.
4. **Злоупотребления:** rate-limit (Redis), защита от перебора e-mail, нейтральные ответы.
5. **Секреты и логи:** ничего секретного и персонального в логах, task.md, ответах агента.
6. **Аудит:** чувствительное действие пишет append-only запись (кто, что, когда, причина).

## Правила

- Пароли — argon2id. Токены — короткоживущий access + ротируемый refresh; инвалидация всех сессий при сбросе пароля.
- Неподтверждённый аккаунт не получает полноценных токенов (AD-28) — спорный момент с V-09, решать в task.md.
- Ссылки verify/reset/delete — одноразовые, с TTL; открытие ссылки ничего не меняет, действие — POST.
- Файлы пользователей — в S3 под непредсказуемыми ключами; выдача — через подписанные URL.
- Парсеры FIT/GPX/KML работают в worker с лимитами по памяти и времени; XML — без внешних сущностей (XXE).
- Секреты — только env; `.env*` в git не попадает; gitleaks в pre-commit и CI.
