# Безопасность

Затронута зона ниже → в task.md обязателен Security checklist; reviewer без него ставит REQUEST CHANGES.

Зоны: аутентификация и сессии, роли, загрузка файлов, публичные ссылки, удаление аккаунта,
персональные данные, внешние вызовы, инфраструктура и секреты, зависимости и реестр пакетов.

## Security checklist (в task.md)

1. **AuthN/AuthZ:** кто может вызвать, где проверяется роль/владение объектом (на сервере, не в UI).
2. **Входные данные:** валидация по контракту, лимиты размера/количества, типы файлов по содержимому, не по расширению.
3. **Данные наружу:** нет лишних полей (e-mail, телефон, внутренние id) в ответах и публичных ссылках.
4. **Злоупотребления:** rate-limit (Redis), защита от перебора, нейтральные ответы.
5. **Секреты и логи:** ничего секретного и персонального в логах, task.md, ответах агента.
6. **Аудит:** чувствительное действие пишет append-only запись (кто, что, когда, причина).

## Правила

- Пароли — argon2id. Токены — короткоживущий access + ротируемый refresh; инвалидация сессий при сбросе пароля.
- Ссылки подтверждения, сброса и удаления — одноразовые, с TTL; открытие ссылки ничего не меняет, действие — POST.
- Файлы пользователей — под непредсказуемыми ключами; выдача — через подписанные URL.
- Разбор пользовательских файлов — в worker с лимитами по памяти и времени; XML — без внешних сущностей (XXE).
- Секреты — только env; `.env*` в git не попадает; gitleaks в pre-commit и CI; `.npmrc` без токена.
- Проверка возраста версий pnpm (`minimumReleaseAge`) — исключение только для `@rkarakulov/*`.
