# База данных — PostgreSQL 18 + PostGIS, Drizzle

## Миграции

- Генерировать: `pnpm --filter @on-bike/api db:generate`; применять: `db:migrate`.
- Сгенерированный SQL читать глазами; править руками можно только с комментарием «почему».
- Миграции **не** выполняются при старте приложения — это отдельный шаг деплоя.
- Деструктивные операции (DROP, сужение типа, NOT NULL без default на заполненной таблице,
  удаление колонки) — только через expand → migrate data → contract в разных релизах и с человеком.
- Установленные мобильные приложения живут долго: схема должна оставаться совместимой с API
  предыдущей версии.

## Схема

- Первичные ключи — UUID v7 (сортируемые по времени).
- Время — `timestamptz`, хранится в UTC.
- Геометрия — `geometry(…, 4326)`; для расстояний в метрах — `geography` или `ST_Transform`.
  Пространственные индексы GIST обязательны на колонках, по которым ищем.
- PostGIS-функции (`ST_DWithin`, `ST_Buffer`, `ST_Intersects` …) — через `sql\`\`` в репозитории, не в сервисе.
- Append-only таблицы (аудит, споры, пересчёты) — без UPDATE/DELETE в коде; при возможности
  закрепить триггером или правами.
- Мягкое удаление пользователя = анонимизация («Удалённый участник»), а не каскадное удаление результатов.
- Персональные и биометрические данные — в отдельных колонках/таблицах, чтобы их было просто
  анонимизировать и не выдавать лишнего.

## Тесты

Каждая миграция проверяется на чистой базе в CI. Запросы с PostGIS — интеграционными тестами на
реальной БД.
