# backend-nest — процесс для apps/api

Правила — в `.claude/rules/backend.md`, `db.md`, `contracts.md`, `security.md`. Этот скил задаёт **порядок**.
Для /task2 и /task3 результаты шагов 1–5 попадают в task.md и утверждаются до кода.

## 1. Placement gate

- Какой модуль `src/modules/<context>` владеет поведением? Нет подходящего — новый модуль только с обоснованием.
- Слой: controller (тонкий) / service (логика) / repository (Drizzle, PostGIS) / `jobs/*.processor.ts` (worker).
- Нужен чужой модуль — только через его `index.ts`; цикл зависимостей → перепроектировать, не `forwardRef`.
- Код нужен ≥2 приложениям (например, разбор трека для pre-check) → `packages/tracks` или другой пакет.

## 2. Reuse check

Прочитай целевой модуль и API `@rkarakulov/api-kit`. Ищи существующие: схемы в `@on-bike/contracts`, репозитории,
утилиты геометрии в `@on-bike/tracks`, guards, процессоры очередей. Запиши, что переиспользуешь и какие дубли запрещены.

## 3. Contract sketch

- Схема запроса/ответа в `packages/contracts/src/<context>/` (zod), коды ошибок, enum статусов.
- Совместимость: новое поле optional; ломающее изменение — новая версия эндпоинта.
- Что **не** принимаем от клиента (время, место, кластер — считает сервер).

## 4. Data & migration plan

- Таблицы, колонки, индексы (GIST для геометрии), constraint'ы.
- Append-only? (аудит, споры, пересчёты) — только INSERT.
- Миграция через `db:generate`; деструктивное — expand → migrate → contract в разных релизах.
- Анонимизация при удалении аккаунта: что становится «Удалённый участник».

## 5. Job design (если есть асинхронность)

- Очередь и имя задачи; payload — только id, не сущности целиком.
- Идемпотентность: `jobId` = доменный id + версия; повторный запуск не дублирует эффекты.
- Ретраи и backoff; что видит организатор при финальном провале (dead-letter → действие в панели).
- Лимиты времени и памяти для разбора файлов и рендеринга (Skia, ffmpeg).
- Межмодульные события — outbox-запись в той же транзакции, публикатор ставит задачу.

## 6. TDD

1. Тест, который падает: unit для сервиса; интеграционный на реальной PostgreSQL + PostGIS для
   репозитория и геозапроса; supertest для HTTP; фикстуры FIT/GPX/TCX для треков.
2. Реализация до зелёного.
3. `pnpm --filter @on-bike/api test`, затем `pnpm check`.

## Красные флаги

Логика в controller · SQL в service · `process.env` вне config · клиентское время в расчёте результата ·
UPDATE аудита · миграция при старте · задача без идемпотентности · `any` · `console.log` ·
биометрия или e-mail в логах.
