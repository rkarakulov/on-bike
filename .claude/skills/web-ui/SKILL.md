# web-ui — процесс для admin и landing

Правила — `.claude/rules/web.md`. Сначала план, потом JSX/Astro.

## 1. UI-план (до кода)

- **Экран и роль:** кто видит (организатор / модератор / админ / гость), что делает.
- **Данные:** какие запросы `@on-bike/api-client`, какие схемы contracts; нет эндпоинта — сначала backend.
- **Компоненты:** что переиспользуем, что новое и где живёт (`src/features/<area>/` для admin).
- **Состояния** каждого запроса — по AGENTS.md §4.12 (скелетон `.skeleton` по раскладке, ошибки с повтором, пусто; мутации — состояние кнопки); optimistic — если уместно.
- **Дизайн-система:** из чего собран экран; чего не хватает в `@on-bike/design-tokens` — какой токен/роль добавляем (а не стиль по месту).
- **Необратимые действия:** модалка с обязательной причиной → append-only аудит на сервере.
- **Строки** — ключи `@on-bike/i18n`; **цвета/типографика/отступы** — CSS-переменные `--color-*`, `--space-*`, `--size-*` и классы `.t-*` из `@on-bike/design-tokens` (admin — тема `protocol`).

## 2. admin — «Протокол»

- Desktop 1440, только светлая тема. Плотные таблицы (TanStack Table): сортировка, фильтры, вкладки кластеров, фиксированная шапка.
- Чек-лист публикации протокола блокирует кнопку и объясняет почему.
- Флаги правдоподобия видны только команде платформы и не блокируют публикацию.
- Биометрия — только в разборе спора; графики HR/мощности по дистанции.

## 3. landing — Astro

- SSR-страница на каждый тип ссылки; данные — серверный запрос к API.
- OG-мета и картинка 1200×630, `apple-itunes-app` для Smart App Banner.
- Состояния: недоступно, карточка отозвана, гонка отменена.
- Клиентский JS — только острова, где без него никак.

## 4. Доступность

Семантические элементы, видимый фокус, клавиатурная навигация по таблицам и модалкам,
`aria-*` для нестандартных контролов, контраст по токенам.

## 5. Проверка

Тесты компонентов (Vitest + Testing Library) на состояния и действия; Playwright для ключевых сценариев;
`pnpm --filter <pkg> build` и `pnpm check`.
